# Enterprise Autonomy

**Repository:** [axisvela/enterprise-autonomy](https://github.com/axisvela/enterprise-autonomy) ·
**License:** See repository · **Language:** Go · **Layer:** Program

> The public introduction and runnable-example program for the AxisVela
> ecosystem.

## The problem

A catalog of products does not explain how they compose. Architects and
engineers need to see a real scenario, follow the evidence across product
boundaries, and understand which piece owns which decision.

Enterprise Autonomy is the composition layer: it shows the products working
together without pretending they are one monolith.

## What it provides

- Public product introductions and repository links.
- End-to-end scenarios and reference-stack overviews.
- Thirteen runnable local demos.
- A technical catalog of local surfaces, ports, and interfaces.
- Adoption guidance and governance patterns.

## Why it matters

- **Fastest way to see the whole system.** Start with a scenario, then follow the
  links into the products that own each step.
- **Cross-product evidence.** The examples show how traces, approvals, and state
  cross boundaries.
- **Adoption path.** The examples are designed to be run locally before a
  production commitment.

## How it fits

Enterprise Autonomy is the program that ties the design-time, runtime, trust,
work, assurance, and human layers together. Its examples are the best starting
point after reading the [ecosystem map](../ecosystem-map.md).
