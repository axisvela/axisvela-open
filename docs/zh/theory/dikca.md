> 知识告诉你什么是事实；控制告诉你允许做什么；架构决定什么系统可以被治理。

## 从 DIKW 到 DIKCA

经典 DIKW 层次——数据、信息、知识、智慧——描述的是认知上升。DIKCA 增加两个非认知层：

| 层次 | 作用 |
| --- | --- |
| **数据** | 原始符号或观测。 |
| **信息** | 相对于观察者和上下文获得意义的数据。 |
| **知识** | 关于事实的主张，带有理由。 |
| **控制** | 对允许行为的约束，以及约束的执行。 |
| **架构** | 使其他层成为一个可治理系统的构成性结构。 |

**自主性**则被理解为*元控制*：系统在架构授权下修改自身控制结构的能力。

## 范畴错误

一个常见错误是把治理当作一种知识。策略文档、系统提示或安全指令可以*表示*规范，
但不*执行*规范。模型可能知道规则，却仍然违反它。知识与控制属于不同逻辑类型。

实践结论很直接：

- 如果约束只是被描述，它是建议。
- 如果约束由架构强制执行，它才是治理。

## 架构作为法则

*Architecture as Law* 主张，架构是可治理 AI 的构成条件。没有显式架构的系统不只是
技术不完整；它的行为无法被有原则地预测、约束和审计。

架构不等同于一张图或一个框架标签。它是约束集合，决定：

- 哪些数据结构是允许的；
- 哪些信息流是有效的；
- 哪些知识主张可以被表示；
- 哪些控制机制可以被执行。

没有架构边界的自主性不是高级智能，而是治理失败。

## 与 AxisVela 的映射

| DIKCA 层 | AxisVela 示例 |
| --- | --- |
| 数据/信息 | 摄取、事件、断言、追踪 |
| 知识 | GNOSIVELA 概念与证据；ONTOVELA 世界状态；MNEMOVELA 记忆 |
| 控制 | AEGIVELA 策略、MODUREGIS 能力、SYMBIVELA 审批、沙箱 |
| 架构 | 契约边界、运行时接缝、证据架构、部署拓扑 |
| 自主性（元控制） | 有界自修改：策略变更、能力注册、计划修订、Agent 生命周期 |

生态对契约、证据和控制平面的强调，正是这一观点的体现：治理必须是结构性的。

## 要点

- 不要把提示词当成策略。
- 让控制层可执行、可检查。
- 把架构当作治理产物，而不仅是工程产物。
- 明确 Agent 在什么条件下可以修改自己的控制。
