## 三个值得了解的思想

### 推理租

如果模型推理是生产的计量输入，平台所有者可以在推理层获取租金。*The Inference Rent*
研究基础模型时代的制造稀缺、物理约束与平台租金持久性。

对采用者而言，实际问题是：

- 哪些成本随使用量增长，哪些是固定成本？
- 如果供应商改变价格或政策，退出成本是多少？
- 路由、缓存或本地模型能否降低依赖？

AxisVela 关联：[NOETIVELA](../projects/noetivela.md) 让模型与端点路由显式化，这是成本
与主权控制的前提。

### 暴露与复制

Exposure–Replication 模型认为，高度可观测、可完全表达的资产，在模型能力跨过特定阈值后
会变得可复制。持久优势会转向隐性、隐藏、不可逆体验性和网络化资产。

对 Agent 构建者，这意味着：

- 单纯代码逻辑是弱护城河；
- 专有上下文、关系与运营证据更重要；
- 验证与信任可能成为溢价。

AxisVela 关联：[GNOSIVELA](../projects/gnosivela.md)、
[ONTOVELA](../projects/ontovela.md)、[TEKMOVELA](../projects/tekmovela.md)
投资于上下文、证据与验证，而不只是生成代码。

### 验证溢价

当生成输出泛滥，稀缺品变成可信验证：知道哪个输出正确、安全、适合决策。这也是为什么
本生态把验证与证据当作产品，而不是测试脚本。

## 用这个视角看自建 vs 采购

| 问题 | 为什么重要 |
| --- | --- |
| 这项能力是商品还是差异化？ | 商品能力适合路由或采购。 |
| 上下文在哪里？ | 上下文与关系比代码更难复制。 |
| 谁拥有证据？ | 证据是审计、学习与信任的基础。 |
| 退出路径是什么？ | 契约与开放接口层降低锁定。 |
| 成本曲线如何？ | 推理密集型设计与确定性设计的 economics 不同。 |
