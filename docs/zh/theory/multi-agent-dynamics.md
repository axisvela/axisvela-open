# 多智能体动力学

[English](../../theory/multi-agent-dynamics.md) | 中文

多智能体系统不是“把一个 Agent 重复多次”。增加 Agent 会改变失败模式：协调成本、共享状态、
权限冲突、涌现行为和组织结构都会成为一等问题。

## 规模变化带来什么

| 单 Agent | 多智能体系统 |
| --- | --- |
| 一个上下文、一个计划 | 共享状态与分叉上下文 |
| 一条权限边界 | 委托链与冲突权限 |
| 一个失败域 | 跨 Agent 的部分失败与恢复 |
| 一条追踪 | 关联追踪与因果归因 |
| 一个生命周期 | 角色、交接、租约与退役 |

UAD 的组织层是合适的视角：Agent 形成角色、权限关系与交互结构。论文的分层结果表明，
异构系统倾向于形成可由交互矩阵预测的层级。把它当作设计信号，而不是自然定律。

## 七个协调维度

Harmovela 定义了多智能体协调层必须处理的七个维度：

1. **事件** — 发生了什么。
2. **任务** — 什么正在执行，处于什么状态。
3. **状态** — 现在什么是真的，如何变化。
4. **上下文/记忆** — 什么在影响决策。
5. **委托** — 谁做什么，带什么权限。
6. **恢复** — 失败后怎么办。
7. **治理** — 谁可以做什么，留下什么证据。

多数多智能体失败是缺少其中一个维度的答案，而不是模型质量问题。

## 常见失败模式

- **重复工作。** 缺少租约或所有权模型，两个 Agent 认领同一任务。
- **状态分叉。** Agent 持有不兼容的世界视图，并各自行动。
- **委托失控。** 权限在 Agent 之间放大，或形成互相委托的循环。
- **协调开销。** 协调消耗超过实际工作。
- **涌现升级。** 局部规则产生无人设计的全局行为。
- **归因丢失。** 出问题时无法重建哪个 Agent 在什么权限下做了什么。
- **复杂度上限。** 治理负载增长超过系统的执行能力。

## 设计规则

1. **命名角色与职责。** 不要依赖涌现分工。
2. **使用租约与声明。** 所有权应可过期、可观测。
3. **通过协议共享状态。** Harmovela 或等价协调层。
4. **限制委托。** 权限移动时应衰减；见 [AEGIVELA](../projects/aegivela.md)。
5. **显式交接。** 交接是带所有者和证据的状态转换。
6. **为部分失败设计。** 恢复是协调维度，不是事后补充。
7. **关注治理阈值。** 设计糟糕的控制会破坏稳定；测量效果。
8. **保留归因链。** 关联追踪与身份是必须的。

## 要点

- 多智能体设计是组织设计。
- 协调必须显式、可观测、可恢复。
- 没有衰减的委托是安全漏洞。
- 测量协调成本与治理负载，而不只是任务吞吐。
