# Agent 架构

[English](../../architecture/index.md) | 中文

架构是治理变得可执行的地方。只存在于提示词里的策略是建议；附着在边界上的策略才是控制。

这部分描述 AxisVela 项目背后的架构模式，不绑定任何单一产品。模式刻意保持可组合：
你可以只采用一个接缝，而不采用整个生态。

## 四个原则

1. **在边界控制。** 把策略、身份和出口控制放在行动跨越边界的地方，而不是提示词中间。
2. **分离平面。** 数据平面执行；控制平面做决定、授权、协调与验证。
3. **证据由构造产生。** 如果行动重要，架构应把证据作为工作的副产品产生。
4. **按形态部署。** 本地优先、服务、混合与边缘部署有不同的信任边界。架构应明确命名它们。

## 与理论的关系

架构部分应用 [Agent 理论](../theory/index.md)中的思想：

- UAD 的认知/计算/组织层变成运行时、控制与项目计划架构。
- DIKCA 的控制与架构层变成可执行控制与结构性契约。
- IIC/AOP 的意图与控制分离变成显式目标、计划、策略与验证。
- PPES 的分布视角变成证据与验证架构。

## 一个提醒

不存在唯一“正确”的架构。正确形态取决于风险、部署边界和你需要的证据。把这些页面当作
模式与权衡目录，而不是强制规定。
