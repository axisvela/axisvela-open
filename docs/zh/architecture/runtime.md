# 运行时架构

[English](../../architecture/runtime.md) | 中文

Agent 运行时是意图变成行动的地方。运行时决定 Agent 能看到什么、能做什么、能做多少、
记录什么，以及如何恢复。

## 组件

| 组件 | 职责 | PRAXO-CORE 接缝 |
| --- | --- | --- |
| **循环** | 决定下一步并在边界停止 | `pkg/agent` |
| **模型** | 产生决策与工具调用 | `pkg/model` |
| **工具** | 以校验过的输入调用能力 | `pkg/tool`、`pkg/toolcall` |
| **记忆** | 组装上下文并存储持久状态 | `pkg/memory` |
| **事件** | 发布发生了什么 | `pkg/event` |
| **策略** | 授权或拒绝行动 | `pkg/policy` |
| **沙箱** | 约束执行 | `pkg/sandbox` |
| **检查点** | 不重复副作用地恢复 | `pkg/checkpoint` |
| **插件** | 在受控边界扩展运行时 | `pkg/plugin` |
| **调度器** | 运行周期或延迟任务 | `pkg/scheduler` |

包名是 PRAXO-CORE 的；职责是通用的。

## 执行循环

```text
观察 → 决定 → 授权 → 行动 → 记录 → 评估 →（重复或停止）
```

- **观察：** 从会话、记忆、工具和事件组装上下文。
- **决定：** 调用模型选择步骤或产生最终答案。
- **授权：** 在行动前评估策略，而不是之后。
- **行动：** 在沙箱中、预算与范围内调用工具。
- **记录：** 写入效果、输入、决定与结果。
- **评估：** 检查目标是否达成或循环是否应停止。

省略授权或记录的运行时不是可治理运行时，只是工具调用循环。

## 运行时不变量

好的运行时让以下不变量显式：

1. **默认拒绝。** 没有授权就没有可用工具。
2. **有界步数。** 循环有最大步数与预算。
3. **行动前授权。** 副作用前检查策略。
4. **效果证据。** 每个重要行动留下记录。
5. **可恢复性。** 失败运行可以恢复，而不盲目重复效果。
6. **上下文隔离。** 会话、租户、工作区相互隔离。
7. **提供商中立。** 模型是接口，不是硬编码厂商。

## 本地与服务运行时

| 关注点 | 本地优先运行时 | 服务运行时 |
| --- | --- | --- |
| 信任边界 | 用户机器 | 服务边界 |
| 身份 | 本地用户 + 工作负载 | 租户 + 工作负载身份 |
| 数据 | 本地文件与存储 | 共享存储与队列 |
| 失败 | 进程崩溃、设备丢失 | 部分失败、网络分区 |
| 证据 | 本地账本与追踪 | 中心证据存储 |
| 适用 | 个人 Agent、桌面工具 | 多用户、长期、受治理工作 |

PRAXOVELA 是本地优先设计；RHEOVELA 是面向服务的持久运行时。两者可以组合。

## 该测量什么

- 每任务步数与成本；
- 工具错误率与策略拒绝率；
- 恢复率与恢复时间；
- 上下文大小与检索质量；
- 证据完整性；
- 人类干预率。

这些是运行时健康指标，不是模型基准。

## 要点

- 循环是简单的部分；接缝才是架构。
- 行动前放策略与沙箱。
- 把效果记录当作一等输出。
- 在需要之前设计恢复。
