# 部署形态

[English](../../architecture/deployment.md) | 中文

同样的架构模式可以部署成不同形态。形态决定信任边界、控制位置与可用证据。

## 四种形态

### 1. 本地优先

Agent 运行在用户机器上。数据与工具在本地；模型可以在本地或远端。

- **信任边界：** 设备与用户会话。
- **控制：** 本地策略、沙箱、能力白名单、本地效果账本。
- **证据：** 本地账本与追踪；需要时导出审计。
- **适用：** 个人 Agent、桌面自动化、离线工作。
- **示例：** PRAXOVELA、嵌入工具的 PRAXO-CORE。

### 2. 单租户服务

Agent 作为组织内部服务运行。

- **信任边界：** 服务边界与企业网络。
- **控制：** 工作负载身份、策略服务、能力目录、网关。
- **证据：** 中心证据存储、流程历史。
- **适用：** 内部自动化、长期工作流。
- **示例：** RHEOVELA、LIMENORA、MODUREGIS。

### 3. 企业混合

部分组件在本地、部分在私有云、部分在边缘。

- **信任边界：** 多个边界，需要显式联邦。
- **控制：** 联邦身份、策略、数据驻留、每个边界的网关。
- **证据：** 带溯源与保留规则的聚合。
- **适用：** 受监管企业、多站点运营。
- **示例：** Enterprise Autonomy 参考栈。

### 4. 边缘与物理

Agent 控制或镜像物理系统。

- **信任边界：** 设备、网络链路与物理世界。
- **控制：** 受限任务、本地安全联锁、人类接管、部署前仿真。
- **证据：** 任务记录、传感器证据、恢复日志。
- **适用：** 机器人、工业系统、远程资产。
- **示例：** KINETOVELA、ONTOVELA 孪生、PEIRAVELA 仿真。

## 部署矩阵

| 关注点 | 本地优先 | 单租户服务 | 企业混合 | 边缘/物理 |
| --- | --- | --- | --- | --- |
| 身份 | 用户 + 设备 | 工作负载 + 租户 | 联邦 | 设备 + 工作负载 |
| 策略 | 本地 | 中心 | 联邦 | 本地安全 + 中心 |
| 能力目录 | 本地白名单 | 中心注册 | 联邦 | 任务专用 |
| 证据 | 本地账本 | 中心存储 | 聚合 | 任务记录 |
| 恢复 | 检查点 | 持久流程 | 多站点 | 安全停止/恢复 |
| 验证 | 单元/追踪 | 集成/契约 | 跨系统 | 仿真 + 现场 |

## 设计问题

1. 行动在哪里跨越信任边界？
2. 哪个控制必须本地化以满足延迟或安全？
3. 哪个控制必须中心化以保持一致？
4. 证据需要在哪里跨设备或站点故障存活？
5. 离线行为是什么？
6. 密钥与凭据如何注入？
7. 更新与模型变更如何发布和验证？

## 从小开始

常见采用路径：

1. 用 PRAXO-CORE 和受限工具集做本地优先试点。
2. 加身份、策略与证据。
3. 把长期工作移到持久工作流运行时。
4. 为外部系统加网关。
5. 扩大自主性前加验证与仿真。
6. 只有组织边界需要时才联邦。

错误做法是因为图好看就从最复杂形态开始。从有真实信任边界的最小形态开始。

## 要点

- 部署形态是架构决定，不是事后补充。
- 控制应位于它所保护的边界。
- 证据与恢复必须匹配形态的失败模式。
- 混合与边缘部署需要显式联邦，而不是希望。
