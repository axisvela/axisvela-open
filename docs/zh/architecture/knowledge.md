# 知识与记忆架构

[English](../../architecture/knowledge.md) | 中文

Agent 需要的不只是上下文窗口。它需要记忆、有据可依的知识，以及关于世界的模型。这些是
不同层次，失败模式也不同。

## 四个层次

| 层次 | 问题 | AxisVela 示例 |
| --- | --- | --- |
| **上下文** | 现在模型眼前有什么？ | 提示组装、检索片段、会话状态 |
| **记忆** | 跨运行应持久什么？ | MNEMOVELA：类型化记录、分支、检索、遗忘 |
| **知识锚定** | 术语与主张意味着什么，有什么证据？ | GNOSIVELA：概念、实体、断言、冲突、范围视图 |
| **世界模型** | 运营环境中什么是真的，何时为真？ | ONTOVELA：双时间状态、断言、孪生快照 |

向量存储本身不是以上任何一层。它只是索引。记忆、知识锚定与世界模型需要结构、生命周期
与溯源。

## 记忆架构

有用的记忆设计回答：

- **存什么？** 情景事件、语义事实、程序性知识、用户偏好、决策。
- **如何寻址？** 按身份、租户、会话、实体、时间或用途。
- **如何检索？** 关键词、向量、图、时近性、重要性，或组合。
- **如何修订？** 追加、分支、合并、取代、遗忘。
- **如何治理？** 保留、同意、访问控制、删除。

MNEMOVELA 强调类型化记录、类 Git 分支、混合检索与受治理遗忘。这些是架构选择，不是功能
勾选项。

## 知识锚定架构

知识锚定是检索与意义之间的桥：

- 概念有定义；
- 实体有稳定身份；
- 主张带证据；
- 冲突显式；
- 视图按用途限定范围。

GNOSIVELA 把输出称为 **grounding view**（知识锚定视图）。关键属性是消费者不仅能看到
上下文，还能看到为什么应该信任它。

## 世界模型架构

运营世界模型必须是时间性和证据性的：

- **有效时间** — 某事何时为真；
- **记录时间** — 系统何时得知；
- **断言** — 谁声称，带什么证据；
- **快照与变更** — 某时点的状态是什么。

ONTOVELA 为孪生与运营状态提供这一层。PEIRAVELA 把世界模型作为仿真的起点。

## 设计规则

1. **上下文与记忆分离。** 长提示不是持久记忆。
2. **记忆与知识分离。** 记住一个主张不等于锚定它。
3. **知识与世界状态分离。** 定义不是观测。
4. **携带溯源。** 每个检索项都应可追踪。
5. **显式新鲜度。** 过期上下文是静默失败。
6. **治理删除。** 遗忘是需求，不是边缘情况。
7. **按用途限定范围。** 规划器、支持 Agent 与审计员可能需要同一知识的不同视图。

## 反模式

- “我们把所有东西放进向量数据库。” 那是索引，不是架构。
- “模型会自己搞清定义。” 它会猜。
- “最新一行就是真相。” 那可能只是最新信念，不是真相。
- “我们从不删除任何东西。” 那是合规与质量问题。

## 要点

- 上下文、记忆、知识锚定与世界状态是不同层次。
- 溯源与生命周期是架构的一部分。
- 检索质量必要但不充分；知识锚定与时间性才让知识可用于决策。
