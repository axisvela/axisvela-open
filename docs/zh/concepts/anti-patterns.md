# 反模式

[English](../../concepts/anti-patterns.md) | 中文

反复出现的错误简表。带控制的详细版本见[实操反模式](../practice/anti-patterns.md)。

## 设计

- **提示词当策略。** 在上下文中描述规则不等于执行。
- **模型当架构。** 模型是组件，不是系统。
- **一个 Agent 包办一切。** 范围与权限无界。
- **向量库当记忆。** 索引不是记忆架构。
- **日志当证据。** 日志用于调试，不用于证明。
- **共享数据库集成。** 耦合 schema 并绕过策略。
- **没有退出路径。** 锁定与无界成本。

## 构建

- **无界工具。** Agent 能做太多。
- **长期共享密钥。** 身份弱、撤销慢。
- **直接外部调用。** 凭据与出口不受控。
- **没有步数或成本限制。** 循环失控。
- **没有幂等的重试。** 重复效果。
- **只测一条快乐路径。** 概率系统失败方式不同。
- **未签名产物。** 供应链风险。

## 运维

- **没有恢复计划。** 失败变成事故。
- **没有撤销路径。** 权限无法收回。
- **没有人类接管。** 系统无法停止。
- **证据不保留。** 无法审计与学习。
- **没有回滚。** 坏变更持续。
- **治理只在最后。** 来不及改设计。

## 元模式

多数反模式共享一个根源：**混淆表示与控制**。文档、提示词、图或日志可以描述规则或行动，
但不执行也不证明它。架构是区别所在。
