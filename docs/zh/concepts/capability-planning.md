# 能力规划

[English](../../concepts/capability-planning.md) | 中文

计划只有在能安全执行并在事后检查时才有用。生态把常被压缩进一个提示词的步骤分成五步。

## 1. 目标

想要什么结果，在什么约束下？目标不是计划。它应陈述期望结果、边界，以及什么算成功。

## 2. 计划

计划把目标、状态、能力与约束变成结构化、可修订的产物。执行前应可解释、可验证。

项目：[ORCHADYN](../projects/orchadyn.md)。

## 3. 能力治理

步骤运行前，系统需要知道能力是否存在、谁可以调用、在什么策略下、留下什么审计。能力目录
让这些显式。

项目：[MODUREGIS](../projects/moduregis.md)。授权由
[AEGIVELA](../projects/aegivela.md) 评估。

## 4. 执行

长期工作需要持久性：重试、补偿、恢复与记录历史。流程实例应跨崩溃存活，而不重复副作用。

项目：[RHEOVELA](../projects/rheovela.md)。

## 5. 人类决定与验证

高风险步骤可能需要审批、异常处理或干预。结果可能需要对照原始意图验证。

项目：[SYMBIVELA](../projects/symbivela.md) 负责人为控制，
[TEKMOVELA](../projects/tekmovela.md) 负责验证。

## 为什么分开

- **每步有不同产物。** 目标、计划、能力决定、流程历史、审批与验证结果不是同一件事。
- **每步有不同所有者。** 业务、架构、平台、安全、运维与保障团队可以各自拥有边界。
- **每步可检查。** 把它们压进一次模型调用会让决定不透明、证据薄弱。

## 一个实用测试

对提议的自主流程，问：

- 运行前我能看到计划吗？
- 我能说出每一步的能力与策略吗？
- 第 3 步失败时，流程能否恢复而不重复第 2 步？
- 谁批准高风险步骤？
- 什么证据证明结果？

如果答案都是“在 Agent 里面”，这个流程还不能被规划、治理或验证。
