# 意图与规格

[English](../../concepts/intent-and-specification.md) | 中文

Agent 需要知道想要什么。听起来简单，但“想要什么”通常是目标、上下文、约束与验收标准的
混合。把它们压进一个提示词，系统就失去了检查是否成功的能力。

## 四个分开的东西

| 元素 | 问题 | 示例 |
| --- | --- | --- |
| **目标** | 想要什么结果？ | 解决履约异常 |
| **上下文** | 现在什么相关？ | 订单状态、库存、策略 |
| **约束** | 什么绝不能发生？ | 超过 500 的退款必须审批 |
| **验收** | 怎么知道成功了？ | 订单发货或退款，证据保留 |

[Prompt Conflation Fallacy](../theory/intent-aop.md) 指的就是把四者都当作“提示词”的错误。

## 为什么分离有帮助

- **可测试。** 验收标准可以变成验证契约。
- **可治理。** 约束可以由策略执行，而不只是描述。
- **可调试。** 结果错误时，能看出哪个元素失败。
- **可复用。** 同一目标可以在不同约束下用不同计划实现。

## 规格质量

有用的规格：

- 对结果**显式**；
- 受约束与能力**限制**；
- 验收标准**可观测**；
- 变化时**版本化**；
- 与证明它的证据**关联**。

这是 Intent-Conditioned Computation 与 Agent-Oriented Programming 的实践面：开发者规定
意图、约束和反馈，Agent 决定执行路径。
