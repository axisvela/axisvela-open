# 能力、技能与工具

[English](../../concepts/capability-skill-tool.md) | 中文

这些词常被互换使用。在可治理系统中，它们是不同层次，有不同所有者和控制。

| 术语 | 是什么 | 治理问题 |
| --- | --- | --- |
| **工具（Tool）** | 暴露给模型的可调用函数或 API | 输入 schema 安全吗？爆炸半径多大？ |
| **能力（Capability）** | 带身份、策略与审计的受治理行动单元 | 谁可以调用，在什么条件下？ |
| **技能（Skill）** | Agent 可使用的打包流程或知识产物 | 它从哪里来，包含什么？ |
| **Agent** | 规划并组合能力以实现目标的行动者 | 谁对它的决定负责？ |

## 区分很重要

- 没有能力包装的工具是未治理行动。
- 没有技能的能力可能太底层，难以可靠使用。
- 没有溯源的技能是供应链风险。
- 没有能力目录的 Agent 只能猜自己能做什么。

## 分层模型

```text
Agent
  └─ 技能（流程/知识）
       └─ 能力（受治理行动）
            └─ 工具（实现）
```

层次不是强制的，但澄清所有权：

- 工具所有者控制实现；
- 能力所有者控制策略与审计；
- 技能作者控制流程与依赖；
- Agent 所有者控制目标与计划。

## 治理含义

- **工具**需要输入校验、沙箱与速率限制。
- **能力**需要目录、策略与调用审计。
- **技能**需要签名、溯源与版本化。
- **Agent** 需要身份、权限、生命周期与证据。

## 常见混淆

- “模型可以调用任何函数”——那是工具面，不是能力模型。
- “技能只是一个提示词”——那它没有溯源，也没有可执行行为。
- “能力只是一个 API”——那它没有策略或审计。
