# 可观测性

[English](../../concepts/observability.md) | 中文

可观测性问系统是否健康。证据问发生了什么以及为什么。Agent 系统两者都需要，但它们不是
同一件事。

## 三种信号

| 信号 | 问题 | 示例 |
| --- | --- | --- |
| **指标** | 多少 / 多频繁？ | 每任务步数、工具错误率、每次运行成本 |
| **日志** | 组件说了什么？ | 工具返回错误 |
| **追踪** | 请求如何流动？ | 模型 → 工具 → 网关 → 外部 API |

这些为运维优化。它们可能被采样、短期保留、非结构化。

## Agent 特有信号

- 每任务步数与循环退出；
- 按类型与结果的工具调用；
- 策略允许/拒绝及原因；
- 上下文大小与检索质量；
- 模型与端点路由决定；
- 恢复事件与恢复时间；
- 人类干预与审批；
- 成本与 token 使用；
- 证据完整性。

## 可观测性 vs 证据

| 可观测性 | 证据 |
| --- | --- |
| 健康与性能 | 重建与审计 |
| 采样常可接受 | 重要行动必须完整 |
| 短期保留 | 按策略保留 |
| 面向运维 | 面向审计与监管 |

如果追踪是结构化、完整、关联并保留的，它可以是证据。指标几乎从来不是。

## 实践规则

1. **用 ID 关联。** 会话、运行、追踪、租户、Agent、能力。
2. **不要记录密钥或完整敏感载荷。**
3. **把运维日志与证据记录分开。**
4. **采样高容量遥测，不采样重要效果。**
5. **对控制平面失败告警**，不只是错误：策略服务宕机、证据存储不可用、审批积压。
6. **让 Agent 决定可见**：步骤、工具、策略、结果。

## 有意义的仪表盘

- 运行开始/完成/失败；
- 策略拒绝率与主要原因；
- 工具错误率与延迟；
- 恢复率；
- 人类干预率；
- 每成功任务成本；
- 证据缺口。

如果仪表盘只显示模型延迟，它不是 Agent 运维仪表盘。
