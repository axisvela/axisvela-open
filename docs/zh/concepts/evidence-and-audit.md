# 证据与可审计性

[English](../../concepts/evidence-and-audit.md) | 中文

日志说某事发生了。证据让你**重建**发生了什么、**验证**它被允许，并在事后**辩护**决定。

## 为什么日志不够

日志通常为运维优化，不为证明。它们可能不完整、可变、缺少上下文，或与授权行动的策略脱节。
当决定被质疑时，“查日志”不是答案。

证据有四个属性：

1. **结构化** — 以已知形状记录行动、输入、决定、结果与身份。
2. **关联** — 连接策略、审批、执行与结果。
3. **可防篡改** — 可检查修改或遗漏。
4. **可保留** — 比产生它的流程活得更久。

## 证据不等于可观测性

可观测性问“系统健康吗？”证据问“我能证明发生了什么以及为什么吗？”系统可以高度可观测
却没有审计轨迹，反之亦然。成熟系统两者都需要。

## 一个实用测试

选一个重要行动，只用产物回答：

- 哪个 Agent 行动？
- 在哪个身份与权限下？
- 哪个策略允许？
- 实际调用了什么？
- 结果是什么？
- 谁批准？
- 行动能否撤销或恢复？

如果任何答案依赖人的记忆或可变仪表盘，证据模型就不完整。
