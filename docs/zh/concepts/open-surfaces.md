# 开放接口层

[English](../../concepts/open-surfaces.md) | 中文

“开源”和“开放接口层”不是同一个主张。AxisVela 两者都用，评估项目时区别很重要。

## 三个层次

### 完全开源

仓库以开放许可证包含实现。

- [PRAXO-CORE](../projects/praxo-core.md) — MIT。
- [TAXOVELA](../projects/taxovela.md) — MIT。
- [Harmovela](../projects/harmovela.md) — Apache-2.0 协议与参考实现。

### 开放接口层

仓库以开放许可证发布集成接口——契约、SDK、示例，有时包含二进制——但运行时核心或企业版
可能单独开发。

生态中多数 `*-open` 仓库属于这种接口层。它们让你无需商业承诺即可评估、集成和构建，
但不承诺整个运行时开源。

### 商业或私有

部分核心与企业版在私有仓库开发，可能增加多租户、高可用、合规包、托管部署等运营能力。

## 如何评估开放接口层

1. 阅读具体仓库的 `LICENSE`。它是最终依据。
2. 检查仓库实际包含什么：契约、SDK、示例、二进制，还是可运行运行时。
3. 在假设生产就绪前运行示例。
4. 查看仓库的发布与支持姿态，而不是摘要。
5. 询问边界：能否在保留契约的情况下替换实现？

## 为什么采用这种模型

干净的开放接口层让独立维护者可以发布有用、可测试的接口，而不假装所有运营功能都免费。
它也保持许可证边界诚实：MIT 框架与 Apache-2.0 接口层是显式的，商业版单独存在。

当前映射见[许可证](../reference/licenses.md)。有疑问时，以仓库为准。
