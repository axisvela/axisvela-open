# 治理 Agent

[English](../../practice/govern-an-agent.md) | 中文

能工作的 Agent 不等于可治理的 Agent。本指南加上让自主性可辩护的控制平面。

## 1. 给 Agent 身份

不要用共享 API key 认证 Agent。使用工作负载身份和短期、持有证明的令牌。

- [EIDOVELA](../projects/eidovela.md) 签发身份并验证工作负载证明。
- [NOMIVELA](../projects/nomivela.md) 记录 Agent、命名空间、权限绑定与生命周期纪元。
- [AEGIVELA](../projects/aegivela.md) 授权行动，并通过 PEP 执行决定。

最少要回答：

- 这是哪个工作负载？
- 属于哪个租户与命名空间？
- 绑定了什么权限？
- 凭据如何轮换与撤销？

## 2. 限制能力

让能力集显式：

- 在受治理目录中发布能力（[MODUREGIS](../projects/moduregis.md)）；
- 给每个能力附加策略与元数据；
- 默认拒绝未知能力；
- 记录每次调用。

能力不只是函数。它有所有者、风险等级、策略和审计轨迹。

## 3. 把策略放在提示词之外

把治理从指令移到执行：

- 行动前评估策略；
- 在边界使用 PEP；
- 委托时衰减权限；
- 支持撤销；
- 记录决定与策略版本。

如果阻止坏行动的唯一东西是系统提示里的一句话，这个行动就没有被治理。

## 4. 为高风险步骤加人类审批

定义“高风险”是什么。例如：

- 破坏性数据变更；
- 金融交易；
- 外部通信；
- 物理执行；
- 权限变更。

把这些步骤路由到 [SYMBIVELA](../projects/symbivela.md) 或等价审批路径。审批应引用计划、
能力、证据与责任人。

## 5. 产生证据

记录证据链：

```text
目标 → 计划 → 能力 → 策略决定 → 身份 → 效果 → 结果
```

按运行时使用效果账本、流程历史或验证证据包。按策略保留。让它可防篡改。

## 6. 测试控制

- 尝试未授权工具。应被拒绝。
- 尝试权限过大的委托。应被衰减。
- 运行中撤销权限。应停止。
- 移除策略服务。高风险行动应失败关闭。
- 篡改证据。系统应检测到。
- 重放失败运行。效果不应重复。

## 治理清单

- [ ] 身份基于工作负载，不是共享密钥。
- [ ] Agent 已注册，有所有者与生命周期。
- [ ] 能力已编目，默认拒绝。
- [ ] 策略在提示词之外执行。
- [ ] 委托会衰减权限。
- [ ] 高风险行动需要审批。
- [ ] 证据连接完整决策链。
- [ ] 撤销与恢复已测试。
- [ ] 人类可以介入。
