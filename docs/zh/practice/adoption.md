# 采用路径

[English](../../practice/adoption.md) | 中文

本指南面向决定是否以及如何采用这个生态的团队。它是实用顺序，不是销售流程。

## 1. 评估

从真实问题开始，而不是产品巡览。

- 阅读[从这里开始](../start-here.md)和[生态地图](../ecosystem-map.md)。
- 从 [Enterprise Autonomy](https://github.com/axisvela/enterprise-autonomy) 选一个
  可运行示例。
- 找出你今天缺少的控制：身份、策略、证据、恢复、验证或集成。
- 检查[许可证](../reference/licenses.md)与开放接口层边界。

**退出标准：** 你能说出需要的接缝与想要的证据。

## 2. 试点

构建能跑通该接缝的最小系统。

- 用 PRAXO-CORE 作为 Agent。
- 一次加一个控制平面。
- 保持工具集小。
- 从第一天记录证据。
- 试点前定义“成功”。

**退出标准：** 试点能运行、能安全失败，并产生可用证据。

## 3. 集成

把试点接到真实系统。

- 把外部访问放到 LIMENORA 或等价网关之后。
- 加身份与权限绑定。
- 让长期工作持久化。
- 为高风险步骤加审批。
- 为发布变更加验证。

**退出标准：** 真实工作流端到端完成，有证据与恢复路径。

## 4. 扩展

只有在控制被证明后才扩展。

- 增加 Agent 与能力。
- 加协调（Harmovela、COORDIVELA）。
- 为更高风险变更加仿真与验证。
- 需要时跨站点或租户联邦。
- 评审成本、延迟与治理负载。

**退出标准：** 系统可以被运行、审计和变更，而不失去控制。

## 自建 vs 采购

| 问题 | 考虑 |
| --- | --- |
| 这项能力是商品吗？ | 路由、模型访问、通用工具可以采购。 |
| 上下文是专有的吗？ | 保留它，它很难复制。 |
| 证据属于你吗？ | 拥有证据链。 |
| 退出成本是多少？ | 优先选择有迁移路径的契约与开放接口层。 |
| 成本曲线如何？ | 推理密集型设计需要路由与预算。 |

## 开放接口层 vs 商业版

`*-open` 仓库是集成接口。它可能足够试点和构建自己的运行时。企业版可能增加多租户、
高可用、合规或托管运营。

不要假设开放接口层就是完整产品；也不要假设每个用例都需要商业版。检查仓库与许可证。

## 风险评审

- 失败爆炸半径多大？
- Agent 能改变现实世界的什么？
- 凭据与数据在哪里？
- 恢复路径是什么？
- 事件后有什么证据？
- 权限能否快速撤销？
- 模型与技能供应链是什么？
- 成本上限是多少？

## 试点清单

- [ ] 一个真实问题与一个成功标准。
- [ ] 一个 Agent、一组受限工具。
- [ ] 从一开始就有身份与策略。
- [ ] 证据被保留。
- [ ] 失败与恢复已测试。
- [ ] 高风险行动有人类审批路径。
- [ ] 试点失败时有移除计划。

## 要点

- 按接缝采用，而不是按整套栈采用。
- 扩大自主性前先证明证据与恢复。
- 保持退出路径开放。
- 不能安全失败的试点不是试点。
