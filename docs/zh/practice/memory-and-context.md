# 记忆与上下文

[English](../../practice/memory-and-context.md) | 中文

上下文窗口是工作集，不是记忆系统。本指南说明如何组合上下文、持久记忆、知识锚定与世界
状态，而不把它们塞进一个向量库。

## 四个层次

| 层次 | 存储 | 用途 |
| --- | --- | --- |
| 上下文 | 运行时组装 | 当前任务、最近轮次、检索片段 |
| 记忆 | [MNEMOVELA](../projects/mnemovela.md) | 持久事实、决策、情景、偏好 |
| 知识锚定 | [GNOSIVELA](../projects/gnosivela.md) | 定义、实体身份、主张、证据、冲突 |
| 世界状态 | [ONTOVELA](../projects/ontovela.md) | 运营状态、时间断言、孪生快照 |

## 上下文组装模式

每一步按以下顺序组装上下文：

1. **任务意图** — 当前目标与约束。
2. **会话状态** — 本次运行发生了什么。
3. **持久记忆** — 相关历史决策与事实。
4. **有据可依的知识** — 定义与证据支持的主张。
5. **世界状态** — 当前与相关历史状态。
6. **工具描述** — 只包含本步骤允许的工具。

然后记录使用了哪些条目。没有溯源的上下文难以调试，也无法审计。

## 记忆模式

### 情景记忆

存储发生了什么：决策、结果、失败。用于学习与连续性，不是真相来源。

### 语义记忆

存储稳定事实与偏好。当它们关于世界时，要锚定。给它们来源与新鲜度策略。

### 程序性记忆

存储可复用流程与技能。版本化。不要让流程在运行之间静默改变行为。

### 工作记忆

留在会话里。不要持久化所有东西。遗忘是功能。

## 知识锚定模式

在决策中使用主张前：

- 解析实体；
- 检查定义；
- 附加证据；
- 检查冲突；
- 按任务与租户限定视图范围。

GNOSIVELA 的知识锚定视图为此设计。如果跳过锚定，模型会用似是而非的猜测填空。

## 世界状态模式

运营决策要查询某时点状态：

- 现在什么是真的；
- 制定计划时什么是真的；
- 之后什么变了；
- 谁断言了它。

ONTOVELA 的双时间模型区分有效时间与记录时间。这让“系统在 T 时刻相信 X”可回答。

## 反模式

- **一个向量库装所有东西。** 它混淆四个层次。
- **没有溯源的上下文。** 无法解释 Agent 为什么使用某个事实。
- **没有遗忘的记忆。** 保留变成负债。
- **没有冲突处理的知识锚定。** 冲突主张被平均成无意义内容。
- **把世界状态当作仪表盘快照。** 它丢失历史与证据。

## 清单

- [ ] 上下文、记忆、知识锚定、世界状态分开。
- [ ] 检索项携带来源。
- [ ] 记忆有保留与删除策略。
- [ ] 主张被锚定并检查冲突。
- [ ] 世界状态是时间性、证据性的。
- [ ] Agent 记录使用了哪些上下文。
